# lgram

Персональний Android-клієнт Telegram на Kotlin + Python (Telethon через Chaquopy).
Версія: див. `version.properties` та `CHANGELOG.md`.

## Архітектура

- **Kotlin (UI)** — весь інтерфейс: екрани, списки, бічне меню.
- **Python/Telethon (мережа)** — `app/src/main/python/lgram/telethon_bridge.py`.
  Викликається з Kotlin через [Chaquopy](https://chaquo.com/chaquopy/) —
  плагін, що вбудовує CPython прямо в APK. З версії 12.0.1 Chaquopy повністю
  безкоштовний і з відкритим кодом (MIT), без обмежень ліцензії.
- **Міст** — `bridge/TelethonBridge.kt` викликає Python-функції з фонового
  потоку (`Dispatchers.IO`); сам Python-модуль тримає власний `asyncio`
  event loop на кожен акаунт у окремому потоці.

## Сховище даних

Усе лежить у `/sdcard/Download/lgram` (НЕ в приватній `data/data`-директорії
застосунку), щоб можна було будь-коли переглянути/скопіювати/видалити вручну:

```
lgram/
  accounts/<id>/session.session   — Telethon-сесія кожного акаунта
  sessions/                        — сюди копіювати готові файли *.session для автоматичного імпорту
  config/accounts.json            — реєстр акаунтів (ім'я, телефон, активність)
  config/credentials.json         — api_id / api_hash за замовчуванням (редагований)
  downloads/                       — файли, скачані вручну через меню
  cache/                           — тимчасові/кешовані медіа
  logs/                            — логи застосунку
```

Щоб додати готову Telethon-сесію вручну, скопіюй файл `*.session` у
`/sdcard/Download/lgram/sessions/`. Під час наступного відкриття або повернення
до застосунку lgram перевірить її з поточними `api_id` / `api_hash`. Якщо
сесія дійсна, вона автоматично з'явиться в списку акаунтів, а файл буде
перенесено до `accounts/<id>/session.session`. Якщо перевірка не пройде,
початковий файл залишиться у `sessions/`.

Дані НЕ шифруються (свідоме рішення для простоти контролю над файлами).

## Права доступу

Застосунок запитує `MANAGE_EXTERNAL_STORAGE` ("Доступ до всіх файлів") при
першому запуску — без нього Android (10+) не дозволить писати довільні файли
(бази даних сесій, логи) поза власною приватною директорією застосунку.

## Збірка

Збірка відбувається автоматично через GitHub Actions
(`.github/workflows/build-apk.yml`) при пуші в `main`, або вручну через
вкладку Actions → Run workflow. Готовий APK з'являється у розділі
"Artifacts" завершеного запуску.

Збірка з NDK/Chaquopy у CI може з першого разу зажадати коригування версій
(NDK, Gradle, AGP) — якщо білд впаде з помилкою про відсутню NDK чи SDK
платформу, подивись лог кроку "Install NDK" / "Build debug APK" і скинь мені
текст помилки, підправимо workflow під конкретну версію раннера GitHub.
